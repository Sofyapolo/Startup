## 3. Проектирование минимального бизнес-прототипа (МБП)

### Выбранный формат

**Лендинг + форма заявки + concierge (ручная обработка)**

| Компонент | Описание |
| :--- | :--- |
| **Лендинг** | 1 страница: заголовок, 3 преимущества, пример дашборда (скриншот), форма записи на демо. |
| **Форма заявки** | Поля: имя, компания, email, ссылка на LinkedIn (опционально). CTA: «Записаться на демо». |
| **Concierge (ручная имитация)** | После заявки HR присылает CSV (анонимизированный). Мы вручную: 1) загружаем данные, 2) имитируем AI-классификацию (читаем ответы, ставим категории), 3) отправляем HR дашборд (PDF / скриншот). |

### Требования к МБП

| Требование | Описание |
| :--- | :--- |
| **Какой результат демонстрирует** | HR получает дашборд с AI-классификацией причин ухода (токсичный лид, выгорание, зарплата, токсичный коллектив) и рекомендации. |
| **Что должен увидеть / сделать пользователь** | Заполнить форму → получить письмо с инструкцией → прислать CSV → через 24 часа получить дашборд. |
| **Целевое действие (CTA)** | «Записаться на демо» → переход к форме. |
| **Какие данные собираем** | Имя, компания, email, ссылка на LinkedIn, размер компании, текущая HRIS. |
| **Причины отказа (в форме)** | «Не сейчас», «Дорого», «Уже есть решение», «Не подходит под наши процессы». |

### Почему такой формат

- **Низкая стоимость:** не нужна разработка AI-модуля и интеграций.
- **Быстро:** запуск за 2–3 дня (лендинг + CRM).
- **Проверяет главное:** готовность HR потратить время, доверие к AI-выводам, ценность дашборда.
- **Риск:** ручная обработка не масштабируется, но для 5–10 пилотов — ок.

## 6. Воронка привлечения и активации + метрики

### Воронка (6 шагов)

| Шаг | Событие | Метрика | Как измеряем | Целевое значение (гипотеза) |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **Контакт / показ** | Количество отправленных сообщений / постов | Счётчик в CRM / LinkedIn | 50 контактов / 1 пост |
| 2 | **Интерес** | Переход на лендинг / ответ на сообщение | UTM-метки, ответы в LinkedIn | CTR ≥10% |
| 3 | **Заявка (демо)** | Заполнение формы «Записаться на демо» | CRM (битрикс / Google Forms) | Конверсия ≥20% от переходов |
| 4 | **Проведена демо-сессия** | Проведён звонок (Zoom) | Календарь / CRM | ≥70% от заявок |
| 5 | **Активация (первый результат)** | HR прислал CSV → получил дашборд | Лог в CRM, факт отправки дашборда | ≥80% от проведённых демо |
| 6 | **Повтор / следующий шаг** | HR согласился на платный пилот / LOI | CRM, письменное согласие | ≥30% от активированных |

### North Star Metric для GTM

**NSM:** Количество HR-директоров, которые после демо прислали CSV и получили дашборд (активация).

*Почему эта метрика:* Она отражает, что пользователь не просто «проявил интерес», а реально дал нам свои данные, получил ценность и увидел результат.

### Time-to-Value (от первого контакта до активации)

| Действие | Ожидаемое время |
| :--- | :--- |
| Отправка сообщения → заявка | 1–3 дня |
| Заявка → проведение демо | 2–5 дней |
| Демо → HR прислал CSV | 1–3 дня |
| CSV → дашборд (ручная обработка) | 1 день |
| **Итого (от контакта до дашборда)** | **5–12 дней** |

| Результат | Действие |
| :--- | :--- |
| Э1 подтвердился (версия А лучше) | Берём версию А как основную. Тестируем следующую итерацию сообщения. |
