# Шаг 1. Актуализация гипотез и цели MVP  

**Целевой сегмент:** IT-компании численностью 50–200 сотрудников (Scale-up). Лицо, принимающее решение (ЛПР): HR-директор или основатель.

**Ключевая проблема:** HR не получает честной обратной связи от уходящих сотрудников, тратит 10+ часов в месяц на ручной анализ, а компания теряет деньги на замене специалистов (3–9 окладов).

**Гипотеза ценности:** Автоматический сбор и AI-анализ истинных причин увольнений экономит время HR и даёт управленческие инсайты для снижения текучести.

**Цель MVP:**
> Проверить, что HR-директор IT-компании в сценарии регулярной потери ключевых сотрудников готов запустить пилотный exit-опрос, получить дашборд с AI-классификацией причин ухода и увидеть в нём пользу (экономия времени, выявление скрытых проблем).

**Проверяемые гипотезы:**
| ID | Гипотеза | Критерий подтверждения |
| :--- | :--- | :--- |
| H1 | HR готов подключить тестовую HRIS (или загрузить данные вручную) для автозапуска опросов. | ≥50% пилотных HR успешно завершают подключение за ≤10 минут. |
| H2 | Уходящий сотрудник проходит опрос в чат-боте и даёт развёрнутые ответы. | Средняя длина открытого ответа ≥20 слов. Доля отказников <30%. |
| H3 | AI-классификация выдаёт понятные инсайты (совпадает с ожиданиями HR в ≥80% случаев). | Оценка точности инсайтов пилотными HR ≥4 из 5. |
| H4 | HR видит ценность в дашборде и готов использовать его для принятия решений. | ≥70% пилотных HR говорят «я бы использовал это в работе» после демо. |

# Шаг 2. Ключевой пользовательский сценарий (User Flow)

**Название:** Полный цикл exit-интервью от увольнения до управленческого действия

| Шаг | Действие | Роль | Экран/точка входа |
| :--- | :--- | :--- | :--- |
| 1 | HR-администратор подключает HRIS (или вручную загружает CSV с сотрудниками). | HR | Экран «Интеграции» |
| 2 | Система синхронизирует список сотрудников и их статусы. | Система | Экран «Сотрудники» |
| 3 | HR создаёт сценарий опроса из готовой библиотеки (5–7 вопросов). | HR | Экран «Сценарии» |
| 4 | HR меняет статус тестового сотрудника на «Увольняется» (имитация триггера). | HR | Экран «Сотрудники» |
| 5 | Система автоматически отправляет ссылку на анонимный чат-бот в Telegram/email. | Система | — |
| 6 | Сотрудник проходит опрос (2–3 минуты). | Респондент | Чат-бот / веб-форма |
| 7 | Ответы анонимизируются и передаются в AI-модуль для классификации. | Система | — |
| 8 | HR получает уведомление и открывает дашборд. | HR | Уведомление → Дашборд |
| 9 | HR видит дашборд с распределением причин ухода, динамикой и рекомендациями. | HR | Экран «Дашборд» / «Аналитика» |
| 10 | HR выгружает отчёт в PDF для руководства. | HR | Дашборд → кнопка «Экспорт» |

# Шаг 5. Техническое задание на MVP (сокращённое)

### Название проекта
Exitl — автоматизация exit-интервью с AI-аналитикой для IT-компаний (50–200 сотрудников).

### Цель MVP
Создать минимальный продукт, позволяющий HR запустить exit-опрос, получить AI-классификацию причин ухода и увидеть базовый дашборд.

### Целевая аудитория
HR-директора и HR-менеджеры IT-компаний Scale-up (50–200 сотрудников).

### Описание продукта (5 предложений)
Exitl — это сервис, который автоматически запускает exit-опросы при увольнении сотрудника. Респондент проходит анонимный опрос в Telegram-боте. Ответы обрабатываются AI, который классифицирует причины ухода («зарплата», «выгорание», «токсичный лид»). HR видит дашборд с агрегированной статистикой и трендами по отделам. MVP даёт первые инсайты без ручной аналитики.

### Функциональные требования (Core в формате user stories)

| ID | User Story |
| :--- | :--- |
| US1 | **Как** HR-администратор, **я хочу** подключить HRIS (или загрузить CSV), **чтобы** синхронизировать сотрудников. |
| US2 | **Как** HR-администратор, **я хочу** создать сценарий опроса из готовых вопросов, **чтобы** быстро запустить exit-интервью. |
| US3 | **Как** HR-администратор, **я хочу** изменить статус сотрудника на «Увольняется», **чтобы** запустить опрос вручную (для теста). |
| US4 | **Как** увольняющийся сотрудник, **я хочу** пройти опрос в Telegram-боте анонимно, **чтобы** честно рассказать о причинах ухода. |
| US5 | **Как** система, **я хочу** автоматически анонимизировать ответы (удалять email/имя/IP), **чтобы** соблюдать 152-ФЗ. |
| US6 | **Как** AI-модуль, **я хочу** классифицировать тексты ответов по категориям, **чтобы** HR видел структурированные причины. |
| US7 | **Как** HR, **я хочу** видеть дашборд с распределением причин ухода по отделам, **чтобы** понимать, где системные проблемы. |

### Критерии приемки (пример для US4 и US6)

| ID | Acceptance Criteria |
| :--- | :--- |
| US4 | 1. Ссылка ведёт в Telegram-бота. 2. Нет полей для ввода ФИО/email. 3. После отправки ответы не содержат идентификаторов. |
| US6 | 1. Категория присваивается каждому ответу. 2. Точность классификации на тестовом наборе ≥80%. 3. HR видит % распределения на дашборде. |

### Нефункциональные требования (6 требований)

| ID | Требование | Категория |
| :--- | :--- | :--- |
| N1 | Все персональные данные хранятся на серверах в РФ. | Безопасность / 152-ФЗ |
| N2 | Время загрузки дашборда не более 3 секунд при 1000 записей. | Производительность |
| N3 | Чат-бот доступен 24/7, uptime ≥99.5%. | Доступность |
| N4 | Все действия администратора логируются. | Аудит |
| N5 | Интерфейс дашборда адаптирован для десктопных браузеров (Chrome, Edge). | Совместимость |
| N6 | AI-модуль обрабатывает ответ за ≤2 секунд. | Производительность |

### Ограничения и допущения (что НЕ делаем в MVP)

- Нет полной автоматической интеграции со всеми HRIS (только 1–2 самые популярные, остальные — ручная загрузка CSV).
- Нет предиктивной аналитики для текущих сотрудников (Risk Score).
- Нет интеграции с Jira/Trello (задачи создаются только внутри дашборда).
- Нет доступа для линейных руководителей (только HR).

### Критерии готовности MVP (Definition of Done)

| № | Критерий |
| :--- | :--- |
| 1 | Реализованы все Must user stories (US1–US7). |
| 2 | Основной user flow (шаги 1–10) проходит без блокирующих ошибок. |
| 3 | Анонимизация работает (проверено на тестовых данных). |
| 4 | Точность AI-классификации ≥80% (на тестовом наборе из 30 ответов). |
| 5 | Настроен сбор метрик (конверсия в опрос, время до инсайта). |
| 6 | Подготовлена инструкция для пилотных клиентов (1 страница). |
| 7 | Проведено smoke-тестирование с 3 тестовыми компаниями (mock-данные). |

### Риски и зависимости

| Риск | Вероятность | Смягчение |
| :--- | :--- | :--- |
| HRIS не даёт API доступ | Средняя | Реализовать ручную загрузку CSV как fallback. |
| AI-модель ошибается на реальных данных | Средняя | Запланировать ручную модерацию первых 50 ответов для дообучения. |
| Сотрудники не проходят опрос | Высокая | Добавить систему напоминаний (2–3 уведомления). |
| Низкая конверсия в пилот | Низкая | Заключить LOI с 2–3 заинтересованными компаниями до старта разработки. |

# Шаг 6. Оптимизация затрат на MVP

### Факторы стоимости и меры оптимизации

| Фактор | Влияние на стоимость | Мера оптимизации (что делаем) |
| :--- | :--- | :--- |
| Интеграция с HRIS | Высокое | На старте поддерживаем только 1 HRIS (например, 1С) с REST API. Остальные — ручная загрузка CSV (заменяем код на инструкцию для HR). |
| AI-классификация | Среднее | Используем готовое NLP API (Yandex GPT / GPT Chat) вместо обучения своей модели. |
| Разработка чат-бота | Среднее | Используем шаблоны Telegram Bot API (open-source). Делаем упрощённого бота без сложных ветвлений (линейный опрос). |
| Дашборд | Среднее | Используем готовые библиотеки графиков (Chart.js / ECharts) и шаблон админ-панели (например, на основе React Admin). |
| Количество экранов / ролей | Высокое | В MVP только одна роль (HR-администратор). Убираем роли аналитика и руководителя (переносим в Later). |
| Аутентификация и права | Среднее | На старте — только email + пароль, без двухфакторной аутентификации и сложного разграничения прав (все видят всё). |
| Тестирование | Низкое | Фокусируемся на smoke-тестировании ключевого сценария, отказываемся от полного регресса. |
| Безопасность данных | Среднее | Используем облачного провайдера с сертификацией (Yandex Cloud / Selectel) вместо собственного сервера (экономия на администрировании). |
| Поддержка мобильных устройств | Низкое | В MVP дашборд только для десктопа (сотрудник проходит опрос со смартфона, но HR работает с ноутбука). |
| Локализация | Низкое | Только русский язык, без перевода на английский (убираем интернационализацию). |

### Итоговые меры по снижению затрат

1. **Замена интеграций ручным вводом** (CSV вместо live API для всех, кроме одной HRIS).
2. **Использование no-code / low-code компонентов** для дашборда и бота.
3. **Перенос «хотелок» в Later** (Risk Score, полноценные интеграции с Jira, роли руководителей).
4. **Готовые шаблоны интерфейсов** вместо дизайна с нуля.
5. **Отказ от сложной инфраструктуры** (один сервер, без микросервисов и горизонтального масштабирования на старте).
