## 1. Описание проекта

| Параметр | Значение |
| :--- | :--- |
| **Название проекта** | Exiti |
| **Краткое описание продукта** | Сервис для автоматизации exit-интервью с AI-аналитикой причин увольнений и рекомендациями по удержанию сотрудников. |
| **Целевая аудитория** | HR-директора и HR-администраторы IT-компаний 50–200 сотрудников (Scale-up). |
| **Текущая стадия проекта** | MVP (прототип) — протестирован на 3 HR-специалистах, собрана обратная связь, сформирован backlog доработок. |
| **Основная проблема пользователя** | HR не получает честной обратной связи от уходящих сотрудников, тратит 10+ часов в месяц на ручную аналитику, компания теряет деньги на замене специалистов. |
| **Ключевая ценность продукта** | Автоматический сбор и AI-анализ истинных причин увольнений с готовыми рекомендациями по удержанию. Экономия времени HR и снижение текучести. |

## 2. Цели и метрики

### 2.1. North Star Metric (NSM)

**NSM:** Количество завершённых exit-опросов с AI-классификацией, по которым HR создал задачу на удержание (или принял управленческое решение).

*Почему эта метрика:* Она отражает главную ценность продукта — не просто сбор данных, а реальные действия по снижению текучести.

### 2.2. Поддерживающие метрики (5)

| № | Метрика | Как измеряем | Целевое значение |
| :--- | :--- | :--- | :--- |
| 1 | Конверсия в регистрацию (лендинг → заявка) | Google Analytics / CRM | ≥20% |
| 2 | Доля успешно завершённых опросов | Статус опроса в БД | ≥60% |
| 3 | Точность AI-классификации | Сравнение с ручной разметкой | ≥85% |
| 4 | % HR, создавших задачу после просмотра дашборда | Лог действий в дашборде | ≥50% |
| 5 | Retention D30 (возврат через 30 дней) | Лог входа в систему | ≥40% |

### 2.3. Цели по периодам

| Период | Цель | Метрика | Целевое значение | Обоснование |
| :--- | :--- | :--- | :--- | :--- |
| **0–3 месяца** | Запустить MVP и проверить базовый спрос | Количество компаний в пилоте | 5 компаний | Нужно подтвердить, что HR видят ценность и готовы тратить время. |
| **3–6 месяцев** | Повысить активацию и собрать данные для дообучения AI | % успешно завершённых опросов | ≥60% | Показывает, что сотрудники готовы проходить опрос, а HR — использовать дашборд. |
| **6–12 месяцев** | Запустить платную модель и получить первых платящих клиентов | Количество платящих компаний | 10 компаний | Подтверждает готовность сегмента платить и экономическую модель. |

### 6.2. Минимальная команда на 3 месяца (ядро)

| Период | Минимальная команда | Кого нужно привлечь позже |
| :--- | :--- | :--- |

### 6.3. Узкие места

| Узкое место | Риск | Мера снижения |
| :--- | :--- | :--- |
| **Отсутствие UX/UI-дизайнера** | Интерфейс может быть неинтуитивным, что снизит конверсию. | Использовать шаблоны (Tailwind UI), Product Manager выполняет базовую роль дизайнера. |
| **Отсутствие маркетолога** | Каналы привлечения не тестируются, низкий отклик. | Привлечь фрилансера на 5–10 часов в неделю. |
| **Один разработчик на backend и frontend** | Риск задержек, если задачи идут параллельно. | Разделить роли: один разработчик — backend, второй — frontend. |
| **Нет аналитика** | Нет данных для принятия решений. | Product Manager настраивает аналитику (Google Analytics + события в БД). |

## 10. Выводы
