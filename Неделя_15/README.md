## 2. Формализация ключевого сценария и «точек контроля»

### 2.1. Основной end-to-end сценарий (12 шагов)

| Шаг | Действие | Роль | Контрольная точка |
| :--- | :--- | :--- | :--- |
| 1 | HR переходит на лендинг и нажимает «Регистрация» | HR | Вход в воронку |
| 2 | HR заполняет email, пароль, название компании | HR | — |
| 3 | HR подтверждает email (переход по ссылке из письма) | HR | Активация аккаунта |
| 4 | HR входит в систему → видит пустой дашборд (нет данных) | HR | Состояние «пусто» |
| 5 | HR переходит в раздел «Сотрудники» → загружает CSV (шаблон) | HR | Загрузка данных |
| 6 | Система отображает список сотрудников (статус «Активен») | Система | Данные сохранены |
| 7 | HR переходит в раздел «Сценарии» → выбирает готовые вопросы из библиотеки (5–7 вопросов) | HR | Сценарий создан |
| 8 | HR возвращается в список сотрудников, находит тестового сотрудника, нажимает «Отправить опрос» (ссылка в Telegram/email) | HR | Запуск процесса |
| 9 | Сотрудник переходит по ссылке, проходит опрос в Telegram-боте (2–3 минуты) | Респондент | Опрос завершён |
| 10 | Система анонимизирует ответы и отображает их в дашборде | Система | Данные в дашборде |
| 11 | HR открывает дашборд, видит распределение ответов (фильтры по отделам) | HR | Результат получен |
| 12 | HR нажимает «Экспорт PDF» → скачивает отчёт | HR | Результат сохранён |

### 2.2. Контрольные точки (где пользователь может «застрять»)

| № | Контрольная точка | Риск / проблема | Метрика контроля |
| :--- | :--- | :--- | :--- |
| 1 | Регистрация и подтверждение email | Не приходит письмо, ошибка в email | % успешных подтверждений |
| 2 | Загрузка CSV | Неверный формат, кодировка, дубликаты | % успешных загрузок |
| 3 | Создание сценария | Слишком много опций, непонятно | Время на создание (>5 мин — плохо) |
| 4 | Отправка опроса сотруднику | Сотрудник не получил ссылку | % доставленных сообщений |
| 5 | Прохождение опроса сотрудником | Длинный опрос, страх анонимности | % завершённых опросов, длина ответа |
| 6 | Появление данных в дашборде | Задержка обработки, ошибка AI | Время до появления дашборда (<1 мин) |
| 7 | Экспорт PDF | Ошибка генерации, долго | % успешных экспортов, время (<5 сек) |

### 2.3. Альтернативный сценарий (ошибка / повтор / нет данных)

**Название:** Сотрудник не проходит опрос после напоминания (7 шагов)

| Шаг | Действие | Роль |
| :--- | :--- | :--- |
| 1 | HR отправляет ссылку на опрос сотруднику | HR |
| 2 | Сотрудник не проходит опрос в течение 3 дней | Система |
| 3 | Система автоматически отправляет мягкое напоминание (push/email) | Система |
| 4 | Сотрудник игнорирует напоминание → проходит ещё 2 дня | Система |
| 5 | Система отправляет второе (финальное) напоминание | Система |
| 6 | Сотрудник по-прежнему не отвечает → статус опроса «Пропущено» | Система |
| 7 | HR видит в дашборде статус «Нет ответа» для этого сотрудника | HR |

## 3. Проектирование структуры продукта (экраны/модули/сущности)

### 3.1. Структура интерфейса (экраны и состояния)

| Экран | Назначение (шаг сценария) | Основные элементы | Состояния | Переходы |
| :--- | :--- | :--- | :--- | :--- |
| **Лендинг** | Входная точка | Заголовок, преимущества, CTA «Регистрация» | Загрузка | → Регистрация |
| **Регистрация** | Шаг 1–2 | Форма (email, пароль, компания), кнопка «Зарегистрироваться» | Ошибка (email занят), Успех | → Подтверждение email |
| **Вход** | Вход в систему | Форма (email, пароль) | Ошибка (неверный пароль) | → Дашборд |
| **Дашборд (пустой)** | Шаг 4 | Сообщение «Нет данных, загрузите сотрудников», кнопка «Загрузить CSV» | Пусто | → Сотрудники |
| **Сотрудники** | Шаг 5–6 | Таблица сотрудников, кнопка «Загрузить CSV», строка поиска | Загрузка, Пусто, Ошибка (неверный формат) | → Дашборд |
| **Сценарии** | Шаг 7 | Библиотека вопросов (чекбоксы), кнопка «Сохранить сценарий» | Пусто (нет сценариев), Ошибка | → Сотрудники |
| **Дашборд (с данными)** | Шаг 10–11 | Графики (причины ухода), фильтры, кнопка «Экспорт PDF» | Загрузка, Ошибка | → Экспорт PDF |
| **Чат-бот (Telegram)** | Шаг 9 | Приветствие, вопросы, прогресс-бар | Ошибка (некорректный ответ), Успех | — |

### 3.2. Модель данных (сущности)

| Сущность | Поля | Связи |
| :--- | :--- | :--- |
| **Пользователь (HR)** | id, email, пароль (hash), компания, роль (admin), дата_регистрации | → Компания |
| **Компания** | id, название, тариф (pilot/pro/enterprise) | → Пользователь, → Сотрудник |
| **Сотрудник (респондент)** | id, внешний_id (из CSV), имя (только для синхронизации), отдел, должность, статус (активен/уволен), email | → Компания, → Опрос |
| **Сценарий** | id, название, вопросы (JSON: список вопросов с типами), компания_id | → Компания |
| **Опрос** | id, сотрудник_id, сценарий_id, дата_отправки, дата_прохождения, статус (ожидает/пройден/пропущен), ответы (JSON), анонимизированные_ответы (JSON) | → Сотрудник, → Сценарий |
| **Аналитика (дашборд)** | id, компания_id, период, причины (JSON: категория → количество), динамика (JSON) | → Компания |
