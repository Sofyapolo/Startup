# Шаг 1. Контроль соответствия MVP исходным гипотезам  

### Мини-чек

| Параметр | Значение |
| :--- | :--- |
| **Сегмент** | IT-компании 50–200 сотрудников (Scale-up). ЛПР: HR-директор или основатель. |
| **Проблема** | HR не получает честной обратной связи от уходящих сотрудников, тратит 10+ часов в месяц на ручной анализ, компания теряет деньги на замене специалистов (3–9 окладов). |
| **Ценность (value proposition)** | Автоматический сбор и AI-анализ истинных причин увольнений экономит время HR и даёт управленческие инсайты для снижения текучести. |
| **Целевое действие на MVP** | HR-администратор запускает пилотный exit-опрос и получает дашборд с AI-классификацией причин ухода. |
| **Что считаем «успехом»** | Конверсия в целевое действие ≥50%, точность AI-классификации ≥80%, оценка полезности дашборда ≥4 из 5 от пилотных HR. |

**1. Каким образом MVP решает заявленную проблему?**

MVP решает проблему через автоматизацию запуска exit-опросов (сотрудник получает ссылку в чат-бот), анонимизацию ответов (снимает страх «черной метки») и AI-классификацию текстов (HR видит структурированные причины ухода без ручного чтения сотен анкет). Дашборд даёт агрегированную картину по отделам и динамике.

**2. Соответствует ли продукт первоначальной концепции и гипотезам о ЦА?**

Да, соответствует. MVP реализует ровно то, что было заложено в концепцию: автоматический сбор → AI-анализ → дашборд. Целевая аудитория (HR-директора IT-компаний 50–200 сотрудников) сохранилась. Гипотезы о готовности HR подключить HRIS и о ценности дашборда остались неизменными. Небольшая корректировка: в MVP добавлена ручная загрузка CSV как fallback-вариант для компаний без готового API.

# Шаг 2. Аудит функциональности и юзабилити

### Таблица функций текущего MVP

| Функция | Категория (Core/Support/Later) | Какой шаг сценария обеспечивает | Вклад в ценность | Проблемы / Замечания |
| :--- | :--- | :--- | :--- | :--- |
| Интеграция с HRIS (REST API) | Core | Шаг 1–2 | Экономия времени, автозапуск | Требует доступа к API; не у всех клиентов есть. |
| Ручная загрузка CSV | Support | Шаг 1–2 (fallback) | Актуальность данных | Добавлена как fallback; увеличивает ручной труд, но сохраняет ценность. |
| Конструктор сценариев (библиотека вопросов) | Core | Шаг 3 | Быстрый старт, единообразие данных | Пока только линейный опрос, без ветвлений. |
| Чат-бот (Telegram / веб-форма) | Core | Шаг 5–6 | Удобство для сотрудника, анонимность | Нет поддержки WhatsApp; только Telegram. |
| Анонимизация ответов (удаление персональных данных) | Core | Шаг 7 | Соответствие 152-ФЗ, честность ответов | Работает автоматически, но требует проверки на edge-случаях. |
| AI-классификация причин ухода (NLP) | Core | Шаг 8–9 | Глубокий анализ без рутины | Точность может быть ниже на малых выборках. |
| Дашборд (агрегированная статистика, тренды) | Core | Шаг 8–9 | Видимость проблем, основа для решений | Фильтры только по отделу и периоду; нет детализации до конкретного ответа. |
| Уведомления для HR (Telegram/email) | Support | Шаг 8 | Скорость реакции | Реализовано базово; нет настройки порогов. |
| Экспорт отчёта в PDF | Support | Шаг 10 | Удобство для презентаций | Только PDF; нет Excel/CSV. |
| Предиктивная аналитика (Risk Score) | Later | — | Проактивное удержание | Отложено; не влияет на MVP. |

**Какие фичи можно убрать без потери ценности?**
- **Расширенные фильтры дашборда** (например, фильтр по должности) — можно оставить только фильтр по отделу и периоду.
- **Детальная страница каждого ответа** — на MVP достаточно агрегированной статистики.

**Какие фичи стоит упростить?**
- **Интеграцию с HRIS** — на MVP поддерживаем только одну HRIS (1С) с REST API. Остальные — через ручную загрузку CSV.
- **Чат-бот** — делаем линейный опрос без сложных ветвлений (условная логика «если ответ X, то вопрос Y» — в Later).

**Какие фичи нужно добавить, если без них ключевой сценарий «ломается»?**
- **Ручная загрузка CSV** — добавлена как fallback для компаний без API.
- **Система напоминаний** — добавлена, чтобы повысить процент заполняемости опросов.

# Шаг 3. Корректировка функциональности MVP

| Действие | Функция | Обоснование |
| :--- | :--- | :--- |
| **Перенести в Later** | Предиктивная аналитика (Risk Score) | Не влияет на проверку основной гипотезы (сбор и анализ exit-опросов). |
| **Перенести в Later** | Поддержка WhatsApp в чат-боте | Достаточно Telegram для первого пилота; WhatsApp усложняет интеграцию. |
| **Упростить** | Интеграция с HRIS → только 1С + CSV fallback | Снижает техническую сложность; остальные HRIS — в Later. |
| **Упростить** | Дашборд → только фильтры по отделу и периоду | Убираем детализацию до конкретного ответа; достаточно агрегатов. |
| **Добавить в Core** | Ручная загрузка CSV | Критический fallback для компаний без API; иначе они не могут начать. |
| **Добавить в Support** | Система напоминаний (2–3 уведомления) | Повышает процент заполняемости; без неё данные могут не прийти. |

### Итоговый состав MVP (скорректированный)

| Категория | Функции |
| :--- | :--- |
| **Core (6)** | 1. Интеграция с 1С (REST API) + ручная загрузка CSV. 2. Конструктор сценариев (линейный опрос). 3. Чат-бот (Telegram). 4. Анонимизация ответов. 5. AI-классификация причин ухода. 6. Базовый дашборд (фильтры: отдел/период). |
| **Support (3)** | 1. Уведомления для HR. 2. Экспорт PDF. 3. Система напоминаний для респондентов. |
| **Later (4)** | 1. Предиктивная аналитика (Risk Score). 2. Поддержка WhatsApp. 3. Ветвления в сценариях опроса. 4. Детализация до конкретного ответа. |

# Шаг 4. Метрики и воронка

### North Star Metric (NSM)

**NSM:** Количество завершённых exit-опросов с AI-классификацией, по которым HR принял хотя бы одно управленческое решение (например, создал задачу, инициировал встречу).

*Почему именно эта метрика:* Она отражает главную ценность продукта — не просто сбор данных, а реальные действия по удержанию.

### Воронка взаимодействия (7 шагов)

| Шаг | Действие пользователя | Метрика | Ожидаемая конверсия | Где возможен провал |
| :--- | :--- | :--- | :--- | :--- |
| 1 | Переход на лендинг / регистрация | Визиты → регистрации | 20–30% | Непонятная ценность, длинная форма |
| 2 | Подключение HRIS / загрузка CSV | Регистрации → подключение | 70–80% | Сложность интеграции, отсутствие API |
| 3 | Создание сценария опроса | Подключение → создание сценария | 90% | — |
| 4 | Запуск опроса (триггер / ручной) | Сценарий → первый запуск | 80% | HR забыл протестировать |
| 5 | Прохождение опроса сотрудником | Отправка → заполнение | 40–60% | Нет мотивации, длинный опрос, страх анонимности |
| 6 | Появление данных в дашборде | Заполнение → дашборд | 95% | Сбой AI-классификации |
| 7 | HR принимает решение / создаёт задачу | Дашборд → действие | 50–70% | Нет понятных рекомендаций, сложный интерфейс |

### Таблица метрик

| Метрика | Зачем нужна | Как измеряем |
| :--- | :--- | :--- |
| Конверсия в регистрацию | Оцениваем привлекательность лендинга | Google Analytics / событие в приложении |
| Время до первого запуска опроса | Оцениваем сложность онбординга | Логи действий пользователя |
| % заполненных опросов | Оцениваем удобство чат-бота | Статусы опросов в БД |
| Средняя длина открытого ответа | Оцениваем честность / вовлечённость | Анализ текстов ответов |
| Точность AI-классификации | Оцениваем качество модели | Сравнение с ручной разметкой HR |

# Шаг 5. Подготовка к реальному тестированию (пилот)

### План пилота

| Параметр | Значение |
| :--- | :--- |
| **Кого тестируем** | 5–10 HR-директоров или HR-администраторов из IT-компаний 50–200 сотрудников. |
| **Где ищем** | LinkedIn, Telegram-каналы (HR Community, HR Tech), личные контакты, партнёры. |
| **Формат** | 30-минутная онлайн-встреча (Zoom / Google Meet). Живая демо-сессия с прототипом/MVP. |
| **Сценарий теста** | 1. Краткое введение (2 мин).<br>2. HR подключает HRIS / загружает CSV (5 мин).<br>3. Создаёт сценарий опроса (3 мин).<br>4. Запускает опрос для тестового сотрудника (2 мин).<br>5. Проходит опрос в чат-боте (3 мин).<br>6. Открывает дашборд и смотрит инсайты (5 мин).<br>7. Экспортирует отчёт (2 мин).<br>8. Обсуждение (8 мин). |

### Вопросы после теста (5–8)

1. Насколько понятен и полезен для вас этот сценарий? (1–10)
2. Какая функция показалась самой ценной? А какая лишней или непонятной?
3. Что вас останавливает от внедрения такого решения в вашей компании?
4. Какую максимальную сумму в месяц вы готовы платить за такой сервис?
5. Готовы ли вы подписаться на пилот (2–4 недели бесплатно) после выхода MVP?
6. Что было самым сложным или раздражающим в процессе?
7. Какую функцию вы добавили бы в первую очередь?

### Критерии успеха / провала

| Уровень | Критерий |
| :--- | :--- |
| **Успех** | ≥3 из 5 HR-директоров говорят: «Я бы использовал это в своей компании» **И** ≥2 согласны подписать LOI на пилот. |
| **Частичный успех** | Средняя оценка полезности сценария ≥6/10, но есть сомнения в цене или интеграции. |
| **Провал** | <2 HR видят ценность, средняя оценка <5/10, никто не готов даже пробовать бесплатно. |

### Что делаем, если гипотезы не подтверждаются

| Ситуация | Действие |
| :--- | :--- |
| Низкая конверсия в регистрацию | Переработать лендинг, уточнить ценностное предложение. |
| HR не может подключить HRIS | Упростить интеграцию (только CSV на старте), добавить видеоинструкцию. |
| Сотрудники не проходят опрос | Сократить количество вопросов, добавить напоминания, усилить сообщение об анонимности. |
| Низкая точность AI | Собрать больше размеченных данных, перейти на другую NLP-модель, добавить ручную модерацию первых опросов. |
| HR не видит ценности в дашборде | Добавить готовые рекомендации / инсайты «для действия» (например: «В отделе X высокий риск → провести встречу»). |

### Шаги для реального тестирования

1. **Подготовить среду:** Развернуть MVP на тестовом сервере, подготовить тестовые данные (mock-компания с 50 сотрудниками).
2. **Найти респондентов:** Через LinkedIn, Telegram-каналы, профессиональные сообщества.
3. **Провести демо:** По сценарию выше (5–7 респондентов).
4. **Собрать обратную связь:** Записать ответы на вопросы, замерить время выполнения шагов.
5. **Проанализировать данные:** Выявить самые частые возражения и точки отказа.
6. **Принять решение:** Итерация MVP / смена гипотезы / запуск пилота с живыми клиентами.

### Процесс сбора обратной связи

- **Каналы:** Zoom-запись (с согласия), форма обратной связи после демо, заметки модератора.
- **Типы данных:** Количественные (оценки, конверсии) + качественные (возражения, идеи, фразы).
- **Инструменты:** Google Forms, Miro (доска для заметок), Notion (база респондентов).
